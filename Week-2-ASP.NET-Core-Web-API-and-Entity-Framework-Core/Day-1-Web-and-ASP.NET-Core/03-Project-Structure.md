# 03 — Project Structure

---

## 🎯 What You Will Learn (20 min)

By the end you can:

- Create and run a Web API project
- Name every important file and its job
- Change a file, rebuild, and see the change

---

## Step 1 — Create the Project

```bash
dotnet new webapi -n EmployeeManagement.Api --use-controllers
cd EmployeeManagement.Api
```

> ⚠️ On .NET 8 the template defaults to minimal APIs. Without `--use-controllers` you get a single `Program.cs` with `app.MapGet(...)` and no `Controllers/` folder. Today's lesson is about controllers, so always pass `--use-controllers`.

---

## Step 2 — Run It

```bash
dotnet run
```

You should see:

```text
Now listening on: http://localhost:5189
```

Open a second terminal:

```bash
curl -i http://localhost:5189/weatherforecast
```

You get back the template's sample `WeatherForecast` data. The API works.

---

## Step 3 — The Files

```text
EmployeeManagement.Api/
│
├── Controllers/
│   └── WeatherForecastController.cs      ← sample (we replace it)
├── Properties/
│   └── launchSettings.json               ← dev-only: URLs + environment
├── appsettings.json                      ← settings for every environment
├── appsettings.Development.json          ← settings while developing
├── Program.cs                            ← the entry point
├── EmployeeManagement.Api.csproj         ← project definition
└── WeatherForecast.cs                    ← sample (we replace it)
```

### What each file does

| File | Job | You edit it when… |
|------|-----|-------------------|
| `Program.cs` | Startup + pipeline | Adding middleware, registering services |
| `Controllers/*.cs` | HTTP endpoints | Adding or changing endpoints |
| `appsettings.json` | Base configuration | Changing a setting that applies everywhere |
| `appsettings.Development.json` | Development-only settings | Changing something only while you develop |
| `Properties/launchSettings.json` | Dev-only URL + environment | Changing the port or environment for `dotnet run` |
| `*.csproj` | Project definition (framework, packages) | Adding a NuGet package or changing the target framework |

### `bin/` and `obj/`

After the first build you will also see `bin/` and `obj/` folders.

- They are **generated by the build**.
- You **never** edit them.
- You **never** commit them.

---

## Step 4 — Make a Small Change

Delete the sample files:

```bash
rm Controllers/WeatherForecastController.cs
rm WeatherForecast.cs
```

Build:

```bash
dotnet build
```

The build still succeeds — you have an empty API. The template is gone; you own the project.

> 💡 **Senior Developer Note:** A project structure is a communication tool. A new teammate should find endpoints, types, and logic within seconds — because they live where everyone expects them.

---

## Step 5 — Run It Again

```bash
dotnet run
```

The server still starts. The sample endpoint is gone:

```bash
curl -i http://localhost:5189/weatherforecast
# → 404 Not Found
```

You just cleaned the canvas. Topics 04 and 05 will paint on it.

## 🧪 Think

1. You edit `appsettings.json` but nothing changes. What could be wrong?
2. You change the port in `launchSettings.json` and restart. Where does `dotnet run` pick up the new value?

<details>
<summary><b>Answers</b></summary>

1. If `ASPNETCORE_ENVIRONMENT` is `Development`, the value in `appsettings.Development.json` overrides the one in `appsettings.json`. Check that file.
2. From `Properties/launchSettings.json`. `dotnet run` reads it at startup.

</details>
